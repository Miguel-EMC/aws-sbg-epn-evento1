IAM rápido

Buenas prácticas

  • Root solo cuando sea necesario.
  • MFA habilitado.
  • Diferenciar usuario, grupo, rol y política.
  • Mínimo privilegio.
  • No compartir contraseñas ni access keys.
  • No subir secretos a GitHub.
IAM responde: “¿quién puede hacer qué sobre qué recurso?”
Cloud sin sorpresas

Costos 💸

  • Pago por uso no significa que todo sea gratis.
  • Mostrar Billing / Cost Explorer / Budgets.
  • Un Budget alerta; no es un apagado automático universal.
  • Usar nombres/tags claros.
  • Eliminar recursos al finalizar.
La práctica correcta es saber qué creaste, cuánto tiempo lo necesitas y cómo eliminarlo.

Hands-on

Práctica guiada

0 · Check previo

  • Todos en la región definida.
  • Cuenta/lab/sandbox funcional.
  • Nombre sugerido: epn-evento1-tuNombre.
  • Tag: Event=EPN-Event-01.

1 · Lanzar EC2

Amazon Linux, tipo pequeño permitido por el entorno, red por defecto para simplificar y sin HTTP habilitado todavía.

2 · Primer fallo intencional

Copiar la IPv4 pública y probar http://IP_PUBLICA. Aquí se abre la conversación sobre red y firewall.

3 · EC2 Instance Connect

Entrar desde el navegador para evitar diferencias de SSH local entre Windows, macOS y Linux.

4 · Instalar Nginx

sudo dnf install -y nginx
sudo systemctl enable --now nginx
sudo systemctl status nginx --no-pager

5 · Abrir HTTP/80

Editar el Security Group y agregar HTTP TCP/80. Explicar origen, puerto y por qué el acceso cambia.

6 · Crear la página

sudo tee /usr/share/nginx/html/index.html > /dev/null <<'EOF'
<!DOCTYPE html>
<html lang="es">
<head><meta charset="UTF-8"><title>Mi primera web en AWS</title></head>
<body>
  <h1>Hola desde AWS 🚀</h1>
  <p>Soy TU_NOMBRE y esta es mi primera página corriendo en EC2.</p>
</body>
</html>
EOF

7 · Personalizar + Gallery

Nombre, carrera, frase, colores y contenido. Luego enviar nombre + URL/IP + “qué aprendí hoy”.

8 · Limpieza obligatoria

  • Terminar EC2.
  • Confirmar que no quede Running.
  • Revisar recursos adicionales.
  • Volver a Billing/Budgets como cierre.
